SECCIÓN 5: DURACIÓN EN SEMANAS (WEEKS_DURATION)
════════════════════════════════════════════════════════════════════════════════

Problema actual:
├─ Input tiene value={formData.weeksDuration} con valor 52
├─ El usuario NO puede borrar el número
└─ Si lo borra (intenta), se vuelve a poner 52 (hardcodeado)

Requisitos del usuario:
├─ Campo debe permitir estar COMPLETAMENTE VACÍO
├─ Por defecto (inicial) debe estar VACÍO
├─ Si el usuario intenta crear sin llenar → ERROR
├─ NOT NULL en BD (la restricción)

Reglas de negocio propuestas:
┌─────────────────────────────────────────────────────────────────────────────
│ REGLA 5.1: Estado inicial
│ └─ Campo debe iniciar VACÍO (no con valor 52)
│ 
│ REGLA 5.2: Permitir borrado
│ └─ Usuario DEBE poder dejar el campo completamente vacío
│ └─ Sin restaurar valor automáticamente
│ 
│ REGLA 5.3: Validación
│ └─ Validar en handleSubmit:
│    ├─ SI está vacío → ERROR: "Duración en semanas es requerida"
│    ├─ SI no es número → ERROR
│    ├─ SI < 1 o > 52 → ERROR: "Debe estar entre 1 y 52 semanas"
│    └─ SI válido (1-52) → OK
│ 
│ REGLA 5.4: Backend
│ └─ Ya valida: weeksValue = weeks_duration ? parseInt(weeks_duration, 10) : 52
│ └─ ✅ CORRECTO en backend
│ 
│ REGLA 5.5: Input behavior
│ └─ type="number"
│ └─ min="1" max="52"
│ └─ Permitir value="" (campo vacío)
│ └─ NO restaurar valor si usuario lo borra
└─────────────────────────────────────────────────────────────────────────────

❓ DECISIONES NECESARIAS:
  1. ¿Campo es OBLIGATORIO o puede ser null?
  2. ¿Si está vacío, usar valor por defecto (52) o rechazar?
  3. ¿Mostrar restricción "1-52 semanas" como ayuda?

FLUJO ACTUAL (VERIFICACIÓN COMPLETADA)
════════════════════════════════════════════════════════════════════════════════

❌ PROBLEMA ENCONTRADO:

Actualmente en handleAddClass (TeacherDashboard.tsx línea 155):

1. AddClassModal recolecta schedules en el array
2. Llama onSave(newClass) con { schedules: [...] }
3. PERO TeacherDashboard.handleAddClass() IGNORA los schedules
4. Solo envía: subjectId, sectionId, academicYearId, classroom, weeksDuration
5. POST /api/classes se ejecuta SIN horarios
6. Los schedules NUNCA se guardan en BD

RESULTADO: 
├─ ✅ La clase se crea
└─ ❌ Los horarios se pierden (tabla schedules vacía)


SOLUCIÓN: Opción B (RECOMENDADA)
════════════════════════════════════════════════════════════════════════════════

AddClassModal debe hacer AMBAS llamadas API:

1. AddClassModal.handleSubmit():
   ├─ Valida formData
   ├─ POST /api/classes → obtiene response.data.id
   ├─ POST /api/classes/{id}/schedules → guarda horarios
   ├─ SI TODO OK → llama onSave(newClass)
   ├─ SI FALLA → muestra error, NO llama onSave (modal no cierra)
   └─ Esto garantiza: clases + horarios SIEMPRE juntos

2. TeacherDashboard.handleAddClass():
   ├─ Solo recibe newClass ya guardado
   ├─ Actualiza UI: setClasses([...classes, newClass])
   ├─ Guarda en localStorage
   └─ Cierra modal

VENTAJAS:
├─ AddClassModal es responsable de guardar lo que recolecta
├─ Transacción lógica completa (todo o nada)
├─ Mejor manejo de errores
├─ Mejor UX (error en modal, no cierra hasta arreglarlo)
├─ Separación clara: Modal = guardar datos, Padre = mostrar datos

GARANTÍA: 
└─ "No debe dejar crear la clase sin los horarios" ✅ CUMPLIDO
